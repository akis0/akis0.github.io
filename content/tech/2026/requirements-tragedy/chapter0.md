## 0.1　本章の目的
本書は、ITシステムの要求分析において、なぜ量的分析が反復的に不足するのかを問う。より正確には、要求が自然言語で記述され、関係者が局所合理的に行動し、各部門が責任最小化の誘因を持ち、監査可能性が工学的妥当性より語りやすく、かつ運用負荷が事後的にしか顕在化しないとき、なぜ量的分析が制度的に過少供給されるのかを説明することを目的とする。
このような問題設定は、要求工学、非機能要求論、性能工学、設計過程論、システム安全論、ソフトウェアプロセス論など、複数の研究系譜にまたがっている。したがって本章の役割は、特定の先行研究を逐語的に継承することではなく、本書がどの研究系譜の延長線上にあり、どの点でそれらを横断し、どこに独自の理論的余地を見出すのかを明らかにすることにある。
本章では、要求工学の総論、要求の意味論、非機能要求と品質属性、性能工学、設計過程の制度性、システム安全、そして開発プロセスの動学という七つの系譜を順に概観し、それらに対する本書の位置を示す。

## 0.2　要求工学の全体像
要求工学の代表的総説としては、Nuseibeh と Easterbrook の Requirements Engineering: A Roadmap がある。この論文は、要求獲得、モデリング、分析、妥協、進化といった要求工学の主要領域を体系的に整理し、要求工学を単なる仕様記述技法ではなく、複数の利害関係者、複数の表現形式、複数の時間軸をまたぐ総合的活動として描いた。
この総説の意義は、本書の問題設定を要求工学の外部に置かず、むしろその内部にある未解決の論点として位置づけられる点にある。本書が関心を持つのは、要求工学一般ではない。要求工学の内部において、とりわけ量的境界の欠落がいかにして制度的に再生産されるかという一点である。その意味で、本書は要求工学の新たな総論を目指すものではなく、要求工学の既知の課題群のうち、量的分析の不足という論点を理論的に先鋭化するものである。

## 0.3　要求の意味論と「世界」の重視
要求の意味論に関して、本書に最も近い系譜は、Zave と Michael Jackson に代表される立場である。Zave と Jackson は、要求を単なるプログラム仕様ではなく、世界における望ましい性質として捉える視点を提示した。そこでは、要求とは機械内部の振る舞いそのものではなく、機械が関与することで現実世界において成立すべき状態を表す。Michael Jackson の Problem Frames もまた、ソフトウェア開発問題を機械内部の設計問題としてではなく、機械と世界との関係をどのように構造化するかという問題として整理している。
本書が「存在主張」と「能力保証」を区別し、機能の有無ではなく、運用条件下でその機能が意味を持つ能力として成立するかどうかを問うのは、この系譜を明確に継承するものである。要求が「通知機能が存在する」という主張に縮退するのか、それとも「通知機能が一定の負荷と品質条件の下で成立する」という能力保証として読まれるべきなのかという問いは、まさに要求の意味論の問題である。
ただし本書の関心は、意味論の精密化それ自体にはない。むしろ、存在主張と能力保証の差がなぜ実務で反復的に放置されるのか、その制度的背景を問う点で、Jackson や Zave の系譜からさらに一歩進む。
## 0.4　非機能要求と品質属性
量的分析の問題に最も近い本流は、Chung らによる Non-Functional Requirements in Software Engineering に代表される非機能要求論である。この系譜は、性能、信頼性、保守性、セキュリティ、可用性といった性質を、機能の外側にある付帯条件としてではなく、設計判断を方向づける中心的要因として扱った。また、Bass、Clements、Kazman らによる品質属性シナリオの系譜は、性能や可用性のような抽象的品質概念を、具体的なシナリオに落とし込むことで分析可能にする。
本書はこの系譜と強く接続している。とりわけ、性能や容量のような性質が単なる「非」機能ではなく、機能が現実に成立するための本質的条件であるという点で、本書はこれらの研究と立場を共有する。しかし同時に、本書はこの系譜に対して一つの問いを加える。すなわち、品質属性や非機能要求が重要であることは理解されているにもかかわらず、なぜそれらは十分な精度で書かれないのか、という問いである。
したがって本書は、非機能要求の定義や記述法そのものを拡張するよりも、なぜそれが制度的に痩せるのかを問題にする。その点で、本書はNFR論を継承しつつ、その不足の政治的・制度的条件を問う研究として位置づけられる。

## 0.5　性能工学と容量の早期分析
量的分析を要求段階や設計初期へ持ち込む試みとしては、Connie U. Smith を中心とする Software Performance Engineering (SPE) の系譜が代表的である。SPE は、ソフトウェアシステムが性能目標を満たすようにするための体系的・定量的アプローチであり、アーキテクチャや高位設計の段階から性能をモデル化し、問題を後戻りの高い段階ではなく初期に発見することを目指す。
この系譜は、本書にとって重要な対照対象である。なぜなら、SPE の存在は、量的分析が理論的にも方法論的にも十分に可能であることを示しているからである。すなわち、本書の批判対象は「性能工学が存在しないこと」ではない。そうではなく、そのような量的分析の方法が存在しているにもかかわらず、それが要求分析の現場に十分に組み込まれないのはなぜかという点こそが、本書の中心問題である。
言い換えれば、本書は性能工学の不在を論じるのではなく、性能工学が制度的に要求分析の周縁へ追いやられやすい理由を論じる。その意味で、SPE は本書にとって批判対象ではなく、むしろ「本来ありえたはずの要求分析の姿」を示す対照項である。
## 0.6　設計過程の制度性と「合理的設計」の虚構
設計過程の制度性に関しては、Parnas と Clements の A Rational Design Process: How and Why to Fake It が古典的である。この論文は、ソフトウェア開発が教科書的に完全に合理的な順序で進むことはなく、それでも後からは、あたかも合理的設計であったかのように表象されることを論じる。
この議論は、本書の前提4、すなわち「監査可能性は工学的妥当性より語りやすい」と極めて深く接続している。要求分析において量的境界が欠落していても、文書は整然としており、会議体は機能しており、承認履歴も残っているならば、制度上は「適切に進んだプロセス」が成立してしまう。ここでは、要求の内容よりも、それがどのような手続きを経て承認されたかが前景化される。
本書が描こうとする悲劇は、この「合理的設計の虚構」の要求工学版とみなすことができる。すなわち、要求は存在し、レビューも行われ、承認も得られ、試験も通過している。しかしその内部では、能力保証として書かれるべき内容が、存在主張へと痩せ細っている。このとき、制度は工学的に正しいものではなく、後から語りやすいものを勝たせている。
## 0.7　システム安全と構造的失敗
個人の誤りではなく構造に着目するという点で、Leveson の Engineering a Safer World も本書にとって重要である。Leveson は、安全問題を部品故障や個人ミスの集積ではなく、複雑な社会技術システムにおける制御問題として捉えた。そこでは事故は、異常な部品や愚かな個人の存在からではなく、正常に見える要素の結合と制御の失敗から生じる。
本書もまた、量的分析の欠落を、関係者の無能や不誠実さに還元しない。むしろ、自然言語要求、局所合理性、責任最小化、監査可能性の優位、運用負荷の遅延顕在化という、いずれも単体では病理と呼べない前提の結合から、悲劇が構造的に創発すると考える。その点で、本書は Leveson の社会技術システム論と強く響き合う。
もっとも、両者の問題関心は一致しない。Leveson が主として安全と事故を扱うのに対し、本書は要求分析における能力保証の痩せ細りを中心問題に置く。本書の悲劇は、ただちに死傷事故に至るものだけでなく、停止、遅延、滞留、誤配、責任の曖昧化、運用部門への負債転嫁といった、より広い意味での制度的失敗を含む。

## 0.8　ソフトウェア開発プロセスの動学
さらに一歩進んで、ソフトウェア開発そのものを動的システムとして扱う研究としては、Kellner、Madachy、Raffo による Software Process Simulation Modeling の系譜がある。彼らはソフトウェア開発プロセスをシミュレーション対象として捉え、戦略管理、プロセス改善、教育訓練などへの応用可能性を論じた。その後のレビュー研究も、SPSM が開発プロセスの動学や不確実性を扱いうることを示している。
本書は直接にシミュレーション研究を行うものではないが、問題設定においてこの系譜と接続しうる。なぜなら、本書の中心命題は、量的分析の不足を静的な欠陥ではなく、局所合理性と遅延顕在化のもとで安定化する動学的過程として理解するからである。量的分析は単に「抜けている」のではない。要求分析の場で劣後し、設計で先送りされ、試験で温存され、最後に運用で顕在化する。この時間的推移は、明らかに動学の問題である。
したがって、本書は SPSM を継承してモデル化を行うわけではないにせよ、要求分析を一回限りの静的判断ではなく、時間を通じて意味と責任が移送される制度的動学として描こうとする点で、この系譜と共鳴している。

## 0.9　本書の位置づけ

第一に、本書は Jackson や Zave の系譜を継ぎ、要求を機械内部の仕様としてではなく、世界における能力保証として理解する。要求は、単にソフトウェアが何を実装しているかを述べるものではない。それは、当該ソフトウェアが現実の利用環境において、どのような能力を成立させるべきかを記述するものである。<br>

第二に、本書は Chung や Bass らの系譜を継ぎ、性能、可用性、容量、回復性、観測可能性といった品質属性が、機能の外部にある付帯条件ではなく、機能が現実に成立するための本質的条件であることを認める。「通知できる」「検索できる」「認証できる」という文言は、それらが一定の負荷、遅延、成功率、障害条件のもとで成立するときにのみ、業務上意味を持つ。<br>

第三に、本書は Smith の Software Performance Engineering に近い問題意識を持つ。すなわち、性能や容量の問題を後工程で初めて扱うのではなく、要求分析や設計初期の段階から対象化すべきであるという立場である。ただし本書の関心は、性能工学の方法そのものを展開することにはない。むしろ、そのような方法が存在し、重要性も広く認識されているにもかかわらず、なぜ要求分析の現場では十分に書き込まれないのかを問う点にある。<br>

第四に、本書は Parnas や Leveson の議論に接続し、失敗を個人の愚かさや怠慢に還元しない。ソフトウェア開発の過程は、しばしば後から合理的であったかのように記述される。また、複雑な社会技術システムにおける失敗は、単一の部品故障や単一の人間の誤りではなく、複数の正常な構成要素の相互作用から生じうる。本書もまた、量的分析の欠落を、無能な個人の失敗としてではなく、制度的・構造的条件の結合から生じる悲劇として捉える。<br>

第五に、本書は Kellner らのソフトウェアプロセスシミュレーションの系譜とも接続しうる。もっとも、本書は開発プロセスを数理モデルとしてシミュレーションするものではない。むしろ、要求分析における量的分析の不足を、静的な欠陥ではなく、時間を通じて再生産される過程として理解する。量的境界の不足は、要求分析で生じ、設計で温存され、試験で十分には罰されず、最後に運用で顕在化する。この意味で、本書が扱う悲劇は、静的な不備ではなく動学的な過程である。<br>

このように、本書は、要求の意味論、品質属性、性能工学、設計過程の制度性、社会技術システム論、プロセス動学という複数の議論を横断する。ただし、本書の力点は、それらの先行研究を総合的に解説することにはない。むしろ、曖昧な自然言語要求、局所合理性、責任最小化、監査可能性バイアス、運用負荷の遅延顕在化という五つの条件の結合から、量的分析がなぜ後景化しやすいのかを説明する点にある。<br>

既存研究は、それぞれ重要な一部分を照らしている。要求を世界との関係として捉える議論は、存在主張と能力保証の区別を考える手がかりを与える。品質属性や非機能要求の議論は、性能や可用性が機能の成立条件であることを教える。性能工学は、量的分析を初期工程に組み込む方法を示す。設計過程論とシステム安全論は、失敗を個人ではなく構造の帰結として読む視角を与える。しかし、これらを踏まえたうえで、量的分析の不足を、要求分析の意味論、組織内の誘因、文書化と監査の制度、そして運用での遅延顕在化を結ぶ一つの悲劇として描くことは、少なくともこれらの代表的研究の中心主題ではない。ここに、本書の理論的余地がある。<br>

なお、本書は、量的分析の不足を大規模実証によって測定するものではない。むしろ、本書の主張は、量的分析が後景化しやすい制度的機構を記述することにある。ただし、公開仕様の予備的観察からは、量的記述が完全に欠落しているというより、性能節、別紙、機器仕様、運用要件などに局在し、自然言語で記述された機能要求本文へは十分に浸透していない傾向が見られる。すなわち問題は、単に「量がない」ことではない。より精確には、量は存在しても、能力保証の中心ではなく、文書構造の周辺に配置されやすいのである。この「量の局在」こそ、本書が後続の章で検討する悲劇の、より具体的な姿である。
